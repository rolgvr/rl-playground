Search · Rungs 1–2

1 · Pathfinding

Try it in the playground →

Every algorithm in this chapter answers one question: what is the best route from a start to a goal through a graph? On the grid, a node is a cell and its neighbours are the cells above/below/left/right (optionally diagonals). On real streets, a node is an intersection and its neighbours are the roads leading out of it. The algorithms don't care which — they only ever ask four things:

  • successors(node) — the neighbouring nodes and the cost to step to each,
  • heuristic(node) — an estimate of the remaining distance to the goal,
  • start and goal.

Because that interface is all they use, the same nine algorithms run unchanged on a hand-drawn maze and on a city's road network. What differs is only how much of the graph each one explores before it finds the goal — and that gap is the whole lesson.

The shared skeleton

Every search keeps a frontier (nodes discovered but not yet expanded) and a set of visited nodes. It repeatedly pulls a node off the frontier, checks if it's the goal, and otherwise pushes its successors. The only thing that separates the algorithms is the order in which the frontier hands nodes back: 

frontier ← { start }
while frontier not empty:
    node ← frontier.pop()          # ← the choice of which node defines the algorithm
    if node is goal: return reconstruct_path(node)
    for (nbr, step_cost) in successors(node):
        if nbr not seen (or found cheaper):
            record came_from[nbr] = node
            frontier.push(nbr)

BFS makes frontier a FIFO queue; DFS a stack; Dijkstra and A* a priority queue ordered by a cost. Swap the container, get a different algorithm.

Uninformed search — no idea where the goal is

Breadth-First Search (BFS) expands the frontier in rings of equal step count. Because it reaches every node at distance k before any node at distance k+1, the first time it touches the goal it has found the path with the fewest steps. That makes BFS optimal when every move costs the same — but it fans out in all directions, so on a big open grid it visits a huge number of cells.

Depth-First Search (DFS) swaps the queue for a stack: it plunges down one path as far as it can before backtracking. It often reaches a goal quickly and uses very little memory, but the path it returns can be wildly long — DFS optimises for nothing but "keep going." It's the cautionary tale of the group.

Uniform-cost search — when steps cost differently

Add Mud to the maze and a step is no longer free — crossing a mud cell costs 5. BFS breaks here, because "fewest steps" ≠ "cheapest". Dijkstra's algorithm fixes it by ordering the frontier by g(n), the cheapest known cost to reach n from the start, and always expanding the cheapest node next. It's guaranteed to find the minimum-cost path, and BFS is just the special case where every step costs 1. 

g[start] = 0
frontier = priority queue ordered by g
while frontier:
    node = frontier.pop_min()      # cheapest-so-far
    if node == goal: return path
    for (nbr, cost) in successors(node):
        if g[node] + cost < g[nbr]:
            g[nbr] = g[node] + cost
            frontier.push(nbr, priority = g[nbr])

Informed search — using a heuristic

Dijkstra is optimal but blind: it explores outward evenly, spending effort on directions that lead away from the goal. A heuristic h(n) — a cheap guess of the remaining distance — lets us aim. On a grid, straight-line (or Manhattan) distance to the goal; on streets, the great-circle haversine distance.

Greedy best-first orders the frontier by h(n) alone — always step toward whatever looks closest. It's fast and often finds a path with few expansions, but it's fooled by dead ends and walls, so the path can be far from optimal.

A* is the classic. It orders the frontier by

f(n) = g(n) + h(n)

— cost already paid plus estimated cost remaining. It only commits to a node once its total estimated route is the best on the table, so it drives toward the goal without giving up the optimality guarantee. The catch is a condition on the heuristic:

  • Admissible — h never overestimates the true remaining cost. Straight-line distance is admissible because the real road can only be longer. An admissible h makes A* return an optimal path.
  • Consistent — h never drops by more than the step cost between neighbours. Consistency is slightly stronger and lets A* skip re-expanding nodes.

Set h = 0 and A* is Dijkstra. Make h a perfect oracle and A* walks straight to the goal. Real heuristics sit between, and the better the estimate, the fewer cells A* touches — which is exactly what you watch race on the grid.

Weighted A* inflates the heuristic: f = g + w·h with w > 1 (the playground uses 1.5). It reaches the goal faster with far fewer expansions, but the path can be up to w× longer than optimal — a deliberate trade of quality for speed.

Meet in the middle — bidirectional search

A search that fans out from the start touches roughly b^d nodes (branching factor b, depth d). Run two searches — one forward from the start, one backward from the goal — and each only has to reach the halfway point, so together they touch about 2·b^(d/2) nodes: dramatically fewer. When the two frontiers collide, you stitch the halves. The playground includes bidirectional BFS, Dijkstra and A*; the first two stay optimal, and Bi-A* is near-optimal with careful stopping.

The same algorithms on real streets

Rung 2 swaps the grid for a live road graph pulled from OpenStreetMap. Intersections become nodes; road segments become weighted edges whose cost is their length in metres. The heuristic becomes the haversine (great-circle) distance to the destination — admissible, because no road is shorter than the straight line over the Earth's surface. Nothing else changes: the identical A* that solved your maze now plans a route across a city, and the A*-vs-Dijkstra expansion gap you saw on the grid reappears on real roads. That's the point of the shared interface — the lesson transfers.

Reinforcement Learning · Rung 3

3 · Deep Reinforcement Learning

Try it in the playground →

Search knows the whole map up front. Reinforcement learning doesn't: an agent takes actions in an environment, receives a reward, and has to learn a policy — what to do in each state — purely from the consequences. In the playground the agent sees only the game screen (a stack of image layers) and learns Pac-Man or Pong from scratch, with no rules given.

The full tutorial covers: the Markov Decision Process (states, actions, reward, discount γ); value vs policy; the two great families —

  • Value-based: DQN (Q-learning + a neural net + experience replay + a target network), Double DQN (kills over-optimistic value estimates), Dueling DQN (splits state-value from action-advantage), and Dueling-Double.
  • Policy-gradient: REINFORCE (Monte-Carlo returns), A2C (an actor-critic with a bootstrapped/GAE advantage), and PPO (the modern default — reuse data with a clipped, safe update).

The full tutorial covers:
